# 为什么选择 Janus？（及其对比）

Janus AI 是 **CReport 引擎**：它让 AI 智能体能够在值得信赖的上下文层之上生成、部署并治理商业智能（BI）。本页是坦诚版本：说明 Janus 是为了什么、它**不是**什么，以及它与其临近工具有何不同。

## Janus 要解决的问题

智能体无处不在：Claude Code、Cursor、ChatGPT、Aider、LangChain 流水线、企业内部的副驾驶。它们都不了解你的数据*意味着什么*。把它指向数据仓库，它会写出自信、看似合理却错误的 SQL，因为它需要的含义（标准表、已批准的定义、单位、关联路径）存在于 Schema 之外。在这之上构建仪表盘，等于交付了一个看起来可信的谎言。

Janus 为每个智能体提供同一份受治理的上下文，然后让它们把问题转化为真正正确的答案和仪表盘。

## Janus 与其他方案的比较

|  | 原始 LLM 智能体 | 传统 BI 工具 | 纯语义层 | **Janus AI** |
| --- | :---: | :---: | :---: | :---: |
| 为你编写 SQL | ✅（常常出错） | ❌ | ❌ | ✅ 受治理 |
| 了解你的业务定义 | ❌ | 部分，仅限工具内 | ✅（由 Schema 推导） | ✅ + 非 Schema 知识 |
| 生成**并**部署仪表盘 | ❌ | ✅（手动，在工具内） | ❌ | ✅ 由智能体驱动 |
| 通过*你的*智能体工作（Claude Code、Cursor、MCP…） | ✅ | ❌ | ❌ | ✅ |
| 开放、可审阅、对 Git 友好的上下文 | ❌ | ❌ | 部分 | ✅ |
| 跨 22+ 数据源的受治理执行 | ❌ | 每个连接器单独实现 | ✅（仅定义） | ✅ |

有几点区别值得说清楚：

- **对比原始 LLM 智能体：** Janus 补上了智能体所缺少的治理与知识。同一个智能体，得到正确的答案。
- **对比传统 BI 工具：** BI 工具在其 UI 中渲染由人手动构建的仪表盘。Janus 让智能体基于你的上下文*生成*仪表盘，并部署到你自己的托管环境中。
- **对比纯语义层**（dbt Semantic Layer、Cube）：它们从 Schema 定义指标。Janus 的上下文层补充了 Schema 中没有的企业知识（枚举含义、单位、策略、已验证的示例），并在其之上提供生成式 BI 输出。参见[智能体如何从你的上下文中学习？](/oss/concepts/agent_learning)。

## 以下情况 Janus 适合你

- 你希望 **AI 智能体产出可信的 BI**（答案*和*仪表盘），而不仅仅是看似合理的 SQL。
- 你的业务逻辑存在于**数据库之外**，而你的智能体总是搞错。
- 你希望上下文是**开放、可审阅、受版本控制的**，供每个智能体和每个人使用，而不是被锁在某家供应商的 UI 之后。
- 你查询**多种数据源**（Postgres、BigQuery、Snowflake、DuckDB，以及另外 18 种以上），并希望在它们之上获得统一的受治理入口。

## 以下情况请跳过 Janus

- 你只需要从单个 CSV 生成一张一次性图表。
- 你满足于让智能体在没有任何治理的情况下猜测 SQL。
- 你想要一个完全托管、点击即可构建、无需任何设置的 BI 产品。在这种情况下，可以了解 [Janus AI Commercial](https://crossnow.cn)。
